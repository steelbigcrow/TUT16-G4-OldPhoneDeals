## 2. P1（日常回归）

### 2.1 商品浏览与搜索域

- 执行频率：每日
- 入口条件：已完成测试数据重置；搜索页具备多品牌、多价格区间、可分页数据。
- 案例编号列表：`G-03`、`G-04`
- 失败后回滚建议：
  - 回滚最近一次前端筛选/排序组件改动与 `/api/phones` 查询参数适配改动。
  - 暂时关闭新增筛选项或排序项，恢复上一稳定构建版本。

### 2.2 认证与账户安全域

- 执行频率：每日
- 入口条件：准备可重复使用的“已注册账号、重复邮箱、有效邮箱”测试数据；验证码/邮件通道可用。
- 案例编号列表：`A-02`、`A-05`、`A-06`
- 失败后回滚建议：
  - 回滚最近一次登录/注册/找回密码前后端改动（表单校验、错误码映射、鉴权中间件）。
  - 暂停上线新增认证策略，恢复上一版认证配置与 API 路由。

### 2.3 用户交易链路域（收藏夹/购物车/订单）

- 执行频率：每日
- 入口条件：买家账号可登录；存在可售商品；订单与购物车数据可独立清理。
- 案例编号列表：`U-01`、`U-02`、`U-03`、`U-06`、`U-07`、`U-09`、`U-10`
- 失败后回滚建议：
  - 回滚最近一次购物车、库存校验、结算前置校验与订单查询分页改动。
  - 若影响支付前闭环，先下线结算入口变更并恢复稳定购物车服务版本。

### 2.4 卖家运营域

- 执行频率：每日
- 入口条件：卖家账号可登录；存在至少 1 条卖家商品与评论数据。
- 案例编号列表：`S-02`、`S-03`、`S-04`、`S-05`
- 失败后回滚建议：
  - 回滚最近一次卖家商品状态切换、删除流程、评论可见性接口改动。
  - 临时禁用卖家批量操作入口，回退到单操作稳定版本。

### 2.5 管理后台运营域

- 执行频率：每日
- 入口条件：管理员账号可登录；后台用户、商品、评论、订单数据齐全且可搜索分页。
- 案例编号列表：`M-02`、`M-05`、`M-06`、`M-07`、`M-08`
- 失败后回滚建议：
  - 回滚最近一次后台管理 API（用户、商品、评论、订单筛选）及其前端参数映射改动。
  - 关闭新加筛选项/治理动作按钮，恢复上一版后台管理页面与接口契约。

### 2.6 稳健性与异常处理域

- 执行频率：每日
- 入口条件：可构造异常输入、无效资源 ID、非法上传文件；控制台日志可采集。
- 案例编号列表：`R-01`、`R-02`、`R-03`、`R-05`
- 失败后回滚建议：
  - 回滚最近一次错误处理链路改动（全局异常处理、上传校验、前端错误提示组件）。
  - 上线前保留旧版异常兜底逻辑，暂停发布新增错误呈现策略。
